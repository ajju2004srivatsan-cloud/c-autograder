Limits of this report:
1. Finite I/O tests cannot prove mathematical correctness
   Example: A submission passes all 10 hidden tests but fails when the input has extra whitespace or a trailing newline that no test covers, or hardcodes a lookup table for small inputs. The agent still reports 10/10 on correctness.
   Fix:     Combine fixed regression tests with property-based randomized fuzzing against a reference oracle binary.
2. Empirical timing curves can misclassify complexity on noisy hosts
   Example: An O(n) loop with a tiny constant factor finishes in 0.4ms for n=1..100 while OS scheduling jitter adds 0.8ms of variance, causing complexity_estimator to label an O(n) algorithm as O(1) (or vice versa).
   Fix:     Combine AST loop-bound static analysis with hardware instruction counters (perf) rather than wall-clock time alone.
3. Token-shingle similarity can false-positive on short boilerplate problems
   Example: For a 10-line 'add two integers' task, two independent students who write standard scanf/printf with a helper function can exceed 0.85 token cosine similarity despite zero collusion.
   Fix:     Discount template boilerplate tokens and require a minimum AST node count before raising a similarity flag.
4. Heuristic / LLM readability rubrics can be gamed with superficial comments
   Example: A student adds meaningless comments ('// function') and long meaningless variable names ('variable_one_number') over spaghetti logic, receiving 10/10 on readability.
   Fix:     Cross-check comment semantic relevance against AST operations and enforce human TA spot checks on borderline style scores.
